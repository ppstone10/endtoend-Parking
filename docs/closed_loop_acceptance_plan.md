## 1. 本阶段目标与范围

**完成目标：同一候选网络在固定完整验证协议下，关闭安全干预，闭环泊车成功率 ≥70%，碰撞率 ≤10%，两项同时满足。**

网络输入为模拟 LiDAR/Camera 形成的 BEV、车辆状态和目标位姿，网络输出轨迹，由现有 MPC 跟踪。主验收采用 E5，而非仅使用 GT BEV 的 E3；E3 用于定位感知与规划的差异。

安全门禁、几何过滤、分层局部规划和专家回退可以用于独立系统对照，但不得参与自主网络主验收，也不得将其介入后的成功计为网络独立成功。安全门禁基线继续保留。

本阶段优先解决当前静态验证集上的自主闭环能力。严格停稳、T5 动态障碍注入、S9 最终泛化、多车位选优、完整论文实验矩阵及 CARLA/实车在本阶段之后推进；不得把本阶段达标描述为整个 Python 阶段完成。

## 3. 评价纪律

1. 主协议固定数据身份、300 条索引、场景阈值、控制 seed、重规划周期、车辆外廓和真实接触碰撞定义。缺失样本、任务复原失败或整批异常必须显式报告并解决，不通过缩小分母取得达标。
2. 主结果必须采用无干预 E5。每次报告成功、碰撞、振荡/超时、规划/运行异常等完整失败构成，并列出分场景、前进/倒车的结果。
3. 保持现有位置与航向到达判据以便与基线比较。当前判据不要求速度归零和持续停稳；严格停稳另列后续验收，不能把现有成功率直接称为停稳成功率。
4. 当前验证集已被反复用于比较，将其视为固定回归与本阶段准入集，不声称它是未使用过的最终测试集。S9 test 不进入当前调参或选型。
5. 新建训练选型任务集，使用新的任务身份和布局/采样 seed，并与已有专家数据、恢复数据去重。不得从已经参与当前模型训练的数据中切一片后称为独立未见选型集。
6. 每次实验明确一个主要变量，记录初始化权重、数据身份与配比、配置差异、选型规则和运行结果。必要的协同改动需单独说明。
7. 若修改评测器、控制语义或基础几何，必须检查对基线可比性的影响；需要时将基线和候选在同一修正协议下配对重跑，保留旧结果及更正说明。
8. 单 seed 主协议达标后，至少报告 3 个控制 seed（0/1/2）的结果、均值、标准差及分场景差异。该项衡量运行敏感性，不冒充独立训练 seed 的稳定性。主协议 seed=0 的双门槛不由其他 seed 的平均值替代。

## 4. 阶段安排与出口

预计 7–10 个工作日；这是规划估算，不是达标保证。CPU 训练预算和诊断结果可能延长周期。

### P0：冻结基线与诊断入口（约半天）

- 核对并保留第 2 节的模型、数据、参数、任务索引及新生成报告，建立只追加的候选记录。
- 明确 E5/E3/E1/E5s 的输入、轨迹源和干预设置，避免脚本默认参数切回旧模型或旧数据。
- 检查当前输出是否足以回放首次危险转移；不足时仅增加必要的诊断记录，保持算法行为不变。

产物：可复现基线、诊断记录格式、固定的失败任务清单。已有检查覆盖充分时不重复运行整套基线。

### P1：归因 95 条自主失败（约 1–2 天）

按 S8 称重站 → S4 卸载区 → S3 维修区 → S6 装载区的顺序调查。先分析代表性样本，再覆盖全部 77 条碰撞和 18 条振荡；保留成功样本作配对对照。

每条失败记录：首次危险动作/收敛异常的时刻、当时车辆状态与 BEV、网络预测、下一次重规划前的执行段、实际车体扫掠、距目标及位置/航向误差。碰撞应回溯到接触前的安全状态，而非只看终止帧。

必须回答：

- 起点完整车体是否已接触障碍，数据元信息与当前场景复原是否一致？专家基线也有 1 条碰撞，不能预设所有任务初态和专家输出都可靠。
- 原始 BEV 与当前重感知 BEV、目标局部坐标、轨迹局部/全局转换、时间采样是否一致？S8 开环 ADE 很小但 11 条全碰撞，应优先核查这些边界。
- 网络参考的实际执行前缀是否已不可行？远端穿障与下一执行窗口内穿障分开统计。
- 如果参考安全，实际车辆是否因轨迹不可跟踪或控制偏离而接触障碍？
- 在同一碰撞前状态下，专家能否给出并执行恢复轨迹？若不能，继续区分状态不可恢复、标签失败或规划器限制。
- 装载区振荡主要来自方向切换、航向收敛、速度/轨迹时间不一致，还是停止判断？

产物：失败归因表、代表性逐步回放、每类机制的样本数、1–2 个可检验假设。出口：证据足以选择下一项改动；不把尚未证实的机制写成既定根因。

### P2：建立独立选型与小规模回归集（约 1 天）

- 生成与全部已有训练来源无任务身份重叠的新选型任务，覆盖七场景、前进/倒车/原地转向及困难程度。
- 固定选型索引和参数，声明其用途是选型而非最终测试。具体规模依据单轮运行成本确定，避免重现仅 60 条样本导致候选排序失真的问题。
- 固定一批失败代表与原有成功任务，作为低成本回归集；这是已知问题回归，不称为独立泛化验证。
- 明确成功与碰撞的联合选型规则，加入停滞/振荡审查，不只按成功率或开环 loss 选权重。

产物：选型任务身份清单、去重检查、分层统计、回归集、选型规则。P2 可与不依赖其结果的 P1 诊断交错推进。

### P3：小规模单变量对照（约 3–5 天）

由 P1 证据决定路线，不预先认定必须更换架构或增加训练量：

| 已确认机制 | 实施方向 | 关键验证 |
|---|---|---|
| 坐标/时间/场景复原或标签错误 | 局部修复及必要回归 | 原失败能复现并被修复，既有成功不退化 |
| 可恢复偏离状态覆盖不足 | 从训练任务定向采集首次危险动作之前的安全状态，专家重标恢复 | 近端可执行性改善，碰撞降低，机动与场景配比健康 |
| 实际执行窗口的预测误差致碰 | 对照强调近端位置/航向和恢复动作的监督，保留完整轨迹/终点能力 | 执行前缀不可行率降低，完整任务成功率不被停滞抵消 |
| 参考安全而执行偏离 | 检查轨迹可跟踪性、速度剖面和控制接口 | 同一参考下执行改善，配对基线仍可比 |
| 标签对应冲突机动 | 检查示范与机动标签一致性，再决定是否需要条件化或多候选表示 | 冲突存在的证据及隔离实验，而非仅凭猜测换模型 |
| 近目标收敛或停止问题 | 对照修正相应动作/停止监督或执行逻辑 | 减少振荡，位置航向不退化；停车不计为成功 |

训练侧保留原专家数据及历史有效恢复样本，进行身份去重和配比审查；若需要舍弃历史样本，记录理由。新方法/新依赖/新架构在定方案前按 AGENTS.md 做有范围的成熟方法调研。

每个候选先过相关回归和固定小规模闭环；出现可信改善后才扩大到完整 300 条。已有失败路径（全局净空损失反复调权、单纯加大容量、强行保持旧计划等）需要新的针对性证据才重启。连续两次对照无收益时返回 P1 检查假设，不机械追加训练轮数。

产物：每次实验的假设、主要变量、模型/数据/配置、实际结果、继续或停止理由。尚未验证的候选不进入部署权重。

### P4：完整验收与收尾（约 1–2 天）

- 候选在固定完整 E5 主协议执行 300 条，必须成功 ≥210、碰撞 ≤30；同时检查失败分类和分场景变化。
- 用 E3 判断输入表示差异；若改动影响控制或基础模块，再补相应 E1。安全门禁 E5s 作为独立系统对照，防止主网络改进破坏已有系统能力。
- 主协议达标后补控制 seed=1/2，报告与 seed=0 合并的均值、标准差、最差值和困难场景差异。若出现显著失稳，明确限制并调查，不能只发布最好 seed。
- 形成一个候选的最终报告，写明模型身份、命令、数据身份、所有样本去向、主协议双门槛及复核情况。独立训练 seed 的完整研究验证留在论文实验阶段，除非本轮证据显示必须提前调查。

达不到双门槛时结论明确为未达标；记录改善及失败机制，并据证据提出下一轮方案，不通过改阈值、剔除困难场景、引入专家干预或消耗 S9 test 达成表面验收。

## 6. 主要风险与决策

- **平均误差掩盖局部风险**：同时检查执行窗口、完整车体净空与分场景结果。
- **碰撞转成停滞**：成功、碰撞和振荡/超时共同判断改进。
- **小样本选型偏差**：使用新选型任务和完整主协议确认；不以回归案例上的最好成绩定部署。
- **重复调验证集造成偏差**：如实说明固定回归集用途，保留 S9；新增任务必须去重。
- **控制 seed 与训练 seed 混淆**：分别记录并分别解释。
- **停稳/动态能力被过度宣称**：本阶段成功率仍受第 3 节判据和静态入口限制。

## 7. 本阶段之后的顺序

在自主闭环双指标达到本计划标准并完成复核后，依次安排：严格停稳验收 → 动态障碍注入与重规划 → 冻结最终候选并执行 S9 泛化验收 → 多车位选优及完整基线/消融/独立训练 seed/论文图表。若后续新增能力会改变候选模型，重新明确最终测试安排，避免在同一测试集上反复调参。
