## 4. 已排除的方向（**勿重复投入**）

| 方向 | 实验 | 结果 |
|---|---|---|
| **净空损失（阈值 0.3m）** | v18 / v20 | 碰撞 15.4%→46.3%、开环 ADE 0.29→1.32m；v18 还三变量同改 |
| **净空损失（阈值订正 0.2m）** | v27 | 碰撞 26.5%→27.9%（未降），成功率 −8pt |
| **净空损失（分层+连续净空+max 聚合）** | v28 | 碰撞 26.5%（**一丝未动**），成功率 −32pt |
| **场景重加权** | v25 | 碰撞只降 2.2pt，成功率 −11pt |
| **定向 S4/S6 DAgger** | v26 | S4 碰撞 50.0%→67.9%（**变差**） |
| **未平衡 DAgger** | v23 | 恢复集 90.8% 前进 → 碰撞 15.4%→43.4% |
| **调标量损失权重** | 历史多轮 | 长期无提升（调的是与成功判据脱钩的代理目标） |
| **加网络层** | — | 从未需要：终点位姿损失在**不加层**前提下把成功率从 35.3% 提到 72.1% |

### 4.1 四个关于碰撞的猜想，逐一被证否

| 猜想 | 检验 | 结论 |
|---|---|---|
| ① 碰撞体积/余量比车身大 | 评测用 `collision_margin=0`（真接触）；专家最小间隙 0.232m | ❌ 评测侧排除 |
| ② 训练阈值 0.3m 过保守、与示范冲突 | 几何检查：δ=0.3 时 S4 有 **42%** 专家示范被判违规 | ✅ **阈值确实错**，但 v27 订正后碰撞未降 |
| ③ 稠密惩罚摧毁开环 | v27/v28 显示净空损失**根本降不下碰撞** | ❌ 归因错误（原判断作废） |
| ④ 平均聚合稀释梯度 | `occupancy_max` 为二值+对时刻平均；实测 100 点里 2 个危险点 → 稀释到 2% | ✅ **确实稀释**，但 v28 改为 max 后碰撞仍未降 |

### 4.2 阈值几何检查（`docs/closed_loop_final_report.md` 亦有记录）

每格 = 可规划率 / 专家示范可行率（12 条/场景抽查）：

| 场景 | δ=0.0 | δ=0.1 | **δ=0.2** | δ=0.3 | δ=0.4 |
|---|---|---|---|---|---|
| S1 | 100%/100% | 100%/100% | 100%/100% | 100%/100% | 100%/100% |
| S2 | 100%/100% | 100%/100% | 100%/100% | 92%/92% | 92%/92% |
| S4 | 100%/100% | 100%/100% | **100%/100%** | 100%/**58%** | 100%/**0%** |
| S6 | 100%/100% | 100%/100% | **100%/100%** | 100%/**67%** | 100%/67% |

**结论**：`collision_margin=0.2`（车辆配置既有值）是"保留余量且不限制到达"的可用上限；
训练侧额外加 0.1 → 0.3m 属过度限制。**`safety_extra_margin_m` 应为 0。**

## 5. 当前瓶颈的精确表述

**不是阈值、不是聚合、不是惩罚稠密、不是场景过窄、不是车体过大。**

实测数据：

| 量 | 数值 |
|---|---|
| S4 专家最小间隙 | **0.232m** |
| S4/S6 专家间隙中位 | 0.300m / 0.477m |
| 网络轨迹预测误差 ADE | **0.317–0.343m** |
| S4 碰撞率 | 50–68% |
| S6 碰撞率 | 46–53% |

→ **网络任何时刻的预测误差（≈0.32m）都大于场景可操作间隙（0.23–0.30m）。**
碰撞率由"预测误差 vs 场景间隙"这个**比值**决定，与损失函数形状无关——
这解释了为什么四轮损失侧改动对碰撞率全部无效。

**并且**：训练集与评测集在 S4/S6 上**任务身份零重叠**（S4 430 vs 50），
所以这是**泛化失败**而非记忆失败；重加权与定向补采都无法把避障行为泛化过去。

## 6. 建议的下一步（按推荐顺序）

### 路线 A（推荐先做）：推理侧轨迹级几何过滤

- **做法**：在 `NetworkSource` 之后加一层，检查预测轨迹的外廓扫掠；把**进入碰撞的部分
  投影到可行域**，而不是整条接管。
- **依据**：安全门禁（整条接管）已证明"几何检查+修正"能把碰撞压到 **0.0%**（干预率约 15%）。
  本方案是其细粒度版本，能保留更多网络能力。
- **优势**：**不改训练目标**，因此没有摧毁开环的风险；成本低。
- **落点**：`runtime/sources.py` 新增一个包装源；用 `v26` 权重即可验证，无需重训。

### 路线 B：接受纯网络碰撞上限，按 v26+门禁交付

- 门禁三项判据已全部达标（92.6% / 0.0% / 回退失败 0）。
- 纯网络 70%/10% 记为"在当前架构下未闭合"。

### 路线 C（成本最高）：把预测精度提到 0.1m 量级

- 需要换模型结构（更大容量 / 多模态输出）或改监督（预测碰撞概率场而非单条轨迹）。
- 不保证能到 0.1m；且当前 `max_horizon=320`、逐点回归的设定下，0.32m 已是该容量的典型水平。

### 优先级 P0（无论如何都应先做）：补齐评测覆盖

- 当前只覆盖 4 个场景（136/204 条），**S3 紧 bay（历史振荡最集中）完全缺失**；
- 用一个与当前几何/数据身份一致的协议在 `tracked_pivot_v8_3000/val.npz` 上冻结 300 条索引；
- val 达标后**只跑一次 test（S9，300 条）**作为最终验收。

## 7. 操作须知（接手者容易踩的坑）

1. **环境**：一切用 `D:\conda\envs\endtoend-parking\python.exe`，禁止本地 `C:\Python314`。
2. **模型比较必须统一用 `deployment.pt`**：`best_closed_loop.pt` 未校准停止阈值，
   两者实测差约 3pt（v24：0.5 vs 0.31）——这不是评测噪声。
3. **评测逐位可复现**：同 checkpoint + 同索引 → 同结论（见 `tests/test_evaluation_determinism.py`）。
   不需要重复取均值；换 checkpoint 才是差异来源。
4. **单变量纪律**：v18 曾一次同改三个变量导致实验作废。
5. **新增损失模式时必须**：① 检查梯度是否有界；② 启用 `gradient_clip_norm`（项目默认 `None`）。
   v28 首版因"接触项平方 + power-mean 聚合"在首个 epoch 内 NaN。
6. **DAgger 采集必须核对机动配比**：均匀采集会得到 90% 前进的恢复集，
   合并后整体前进占比升高会让碰撞率翻倍。
7. **恢复集配比要在合并端裁剪**：采集端配额只约束全局，目标场景子集仍会失衡
   （实测 4 场景子集在配额 2 下仍为 211/27）。
8. **测试基线**：全仓 `unittest discover -s tests` 现有 **4 项既有失败**
   （S3 净空、S5/T3、校准计数 ×2）。`test_real_easy_case_completes_in_isolated_worker`
   自身耗时 5.13s 对 5.0s 预算，**CPU 高负载时会偶发失败**，不是回归。
