## 3. 已固证的三条根因（可直接引用，不必重验）

1. **输入分辨率低于要通过的间隙**：`bev_meta = {'resolution': 0.25, 'shape': [5,160,160], 'extent': [20,20,20,20]}`
   （40m×40m @0.25m）。S4 专家示范最小间隙 **0.232m ≈ 0.93 格**。
2. **特征层比输入更粗**：`MineParkingNetV1.bev_encoder` 三次 stride-2 → **20×20**，
   1 单元 = 8×8 格 = **2m**，再 `AdaptiveAvgPool2d(1)` 压成一个向量。
3. **解码器每步看不见障碍**：`_ConditionedGRUDecoder` 的 `context` 在 320 步里**固定不变**，
   唯一变化量是上一步的点 → 网络先把整个自由空间压成一个向量，再"闭眼"吐 320 个绝对坐标。

**这三条一次性解释了**：精度三年卡在 0.27–0.47m；四种净空损失全部失败（损失无法创造被输入销毁的信息）；
唯一降低碰撞的是几何过滤器（全系统里唯一在 0.1m 连续几何上工作的部件）；专家零碰撞
（Hybrid A\* 在 0.1m 分辨率上做碰撞检查，比网络细 2.5 倍）。

对照：专家的误差是**有界且被验证**的（0.2m 外廓膨胀吸收离散化误差，平滑后再校验）；
网络的误差是**回归的统计产物**（多模态示范取平均 + 自回归误差累积 + teacher forcing 的 exposure bias）。

## 4. 已排除的方向（**勿重复投入**）

| 方向 | 结论 |
|---|---|
| 净空损失（四种形式：0.3 / 0.2 / 分层连续 / max 聚合） | 全部无效或有害（v18/v20/v27/v28） |
| 数据配比（DAgger 三轮、定向补采、全场景恢复） | 只能让能力在场景间**换位**，不提升总量（先导1/先导2/v38） |
| 标量损失权重、场景重加权 | 长期无提升 |
| 推理侧几何过滤作为能力 | 能把碰撞压到 30% 左右，但只是**把"撞"换成"停"**，不创造能力 |
| 单独加容量 | v37（h256 从头 30 epoch）失败：欠拟合 + 开环 ADE 0.4475 越过准入线 |

**规律：改变"被优化的对象"有效（v19 终点位姿损失 35.3%→58.8%）；在同一对象上加大力度无效。**

## 5. 待执行计划

### P0-A　门禁回退失败归零（**已于 2026-10-12 完成**）

- 结果：v34 协议 E5s 由 **78.3% / 0.0% / 回退失败 2** 变为 **89.0% / 0.0% / 回退失败 0**，三项判据全绿。
- 做法（规范 `SAFE-SHIELD-003`，见 `spec/safety_training.md`）：门禁由"回退不可用即终止回合"改为
  **三级退化阶梯**——主轨迹 → 可信回退 → **最小风险动作**（优先沿用上一条已验证安全参考的尾段，
  否则单点原地保持）；引擎侧在"替换参考通过审查但控制器实际推进仍不安全"时同样退到最小风险动作。
- 分场景：S3 36.5%→**80.8%**、S8 45.5%→**72.7%**、S6 61.4%→70.5%、S1 92.7%→96.4%；碰撞仍 0.0%。
- **性质**：不是"拖时间"换来的——时间/距离比 1.87→1.86、跟踪 RMS 不变、终点误差反而 1.00→0.59m。
- **同时推翻一条此前的根因结论**：原先认为门禁在 S3/S8 的上限受专家滚动重规划限制（E1r 30.8%/45.5%）。
  专家能力**完全未变**，门禁却把 S3 提到 80.8%、S8 提到 72.7% → 那两处的上限其实是**安全层过早放弃**。
- 剩余：`safety_stops` 仍有 16 条（原 49），为最后兜底路径；`expert_fallback_unavailable = 6`、
  `minimal_risk_holds = 0`（退化全部走了"沿用尾段"）。

### P0-B　分辨率假设的否证实验（1–2 天，**唯一还没被否证的技术路线**）

- **试床选 S4**：专家 94% / 网络 22% / 间隙 0.232m ≈ 0.93 格——三个数把假设钉在一起。
- 做法：重建小规模数据集（约 1000 train + 300 val），BEV 换成**近场 12m @0.075m**
  （张量仍是 160×160，算力不变），**`net-v1` 结构与损失一行不改**，从先导1 暖启动训 15–20 epoch。
- 判据（事前定死）：**开环 ADE 是否 < 0.2m**，以及 S4 成功率是否显著离开 22%。
- **成立** → 进 P1-A。**不成立** → 分辨率假设被否证，纯网络口径正式关闭，转 P1-B。
- 注意：训练只读 npz，**任何输入侧改动都必须重建数据集**，这是这条路的固定成本。

### P1-A　表征改造（仅当 P0-B 成立；数周级）

解码器每步读局部几何（`_context()` 同时返回 context 与特征图，解码按当前点采样局部 patch 或净空值 concat 进
`input_projection`）+ 输出多模态/带不确定性（每步 (μ, logσ²) 用 NLL，或 K 模态按净空选）。
注意：**喂净空是给"输入"，不是给"损失"**——这正是四种净空损失失败的原因。

### P1-B　关闭纯网络口径后的转向

交付"网络 + 运行时安全层"（门禁），把"误差 ≈ 余量"与分场景适用域作为结论；资源转向 P2-B。

### P2-A　评测与选型稳健化（全程并行，成本小）

选型子集从 80–100 条扩到全部 300；用 top-k 平均而非单点最高；300 条上二项标准误 ±2.8pt，
**低于 5pt 的差异不作为改进**。

### P2-B　S3/S8 的专家滚动天花板专项

E1r 在 S3 只有 30.8%（**36/52 是超时、0 碰撞**）、S8 45.5%。这是**架构/场景问题**，与网络无关：
同一规划器"规划一次"是 100%（E1），"每 10 步重规划"就掉到 30.8%。方向：中间态的轴线对齐、
按需重规划 / K 值 / 分层子目标。修好它，专家口径可从 83.7% 抬到接近 95%，网络口径随之抬升。

### P3　论文口径与 M4 实验矩阵

基线组（FR-BASE-01/02）、主网格、消融、可视化 V2/V4/V5、多车位选优（FR-SELECT，完全空白）。

## 7. 口径与陷阱（会静默出错的地方）

1. **`_load_protocol` 的同源问题（已在代码中修，但要知道它发生过）**：输出目录与协议目录为**兄弟关系**时，
   会向上找到父目录的**旧**协议；把新协议索引套在旧数据上，样本因"无法复原"被静默丢弃——
   实测产出过"183 条 / 4 场景、S3/S5/S8 整段消失"却看起来完全合理的报告。
   现在 `--indices-file` 指向的协议优先，且运行开头会打印协议数据与索引条数，**每次都看一眼这两行**。
2. **选型在噪声上挑最高点**：相邻 checkpoint 的闭环选型得分在 **0%↔65%** 之间跳
   （v37：0/0/14/1/0；v38：25/4/65/39/25），说明策略对权重高度敏感。**模型间 5pt 以内的差异不算改进。**
3. **推理耗时是墙钟量**：并发负载下不可比（同架构的 v26 报 5.0ms、v38 报 11.6ms）。
   空载复测：h128 均 11.3ms、h256 14.8ms——**128 维基线本身也超过 NFR-05 的 10ms**，需单独查清口径。
4. **开环与闭环脱节**：v38 开环最差（ADE 0.4746 不达标）却闭环选型最好（65%/28%）。
   **开环指标不能作为闭环选型或准入依据**，且准入要求"先开环后闭环"——两个不达标的模型即由此被挡。
5. **`runs/` 与 `data/` 都在 `.gitignore`**：所有评测报告、checkpoint、恢复数据集都不入库，只留本地。
6. **test（S9，300 条）闭环从未执行**：开环已达标（ADE 0.216 / FDE 0.189），闭环按流程待 val 达标后**只跑一次**。
