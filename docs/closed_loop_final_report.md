## 0. 结论摘要

| 口径 | 验收线 | 起点 | **终点** | 达标 |
|---|---|---|---|---|
| 纯网络 成功率 | ≥70% | 33.8% | **72.1%**（E5，传感器 BEV） | ✅ |
| 纯网络 碰撞率 | ≤10% | 13.2% | **23.5%** | ❌ |
| 门禁 成功率 | ≥70% | 71.6% | **92.6%** | ✅ |
| 门禁 碰撞率 | ≤5% | 0.0% | **0.0%** | ✅ |
| 门禁 回退失败 | =0 | 未核验 | **0** | ✅ |
| 开环 Val ADE / FDE | ≤0.40 / ≤0.80m | — | **0.343 / 0.407m** | ✅ |

**一句话结论**：纯网络成功率首次跨过 70% 准入线；**唯一未闭合项是碰撞率（23.5% vs ≤10%），
且碰撞集中在 S4 卸载区（50–68%）**。门禁口径全部达标，可作为交付基线。

**本轮最大的认知修正**：瓶颈**不是网络容量、不是微调次数、不是感知质量**，
而是**监督目标与成功判据不对齐**——把损失从"整条轨迹逐点平均误差"改为
"只压预测轨迹最后一点 + 航向加权"，**在不加任何一层网络的前提下**
把闭环成功率从 35.3% 推到 72.1%。

## 1. 目标与验收线（权威定义）

`docs/training_guide.md`「正式验收」：

- 开环：Val ADE ≤0.40m、Val FDE ≤0.80m、长度 MAE ≤30 点、停止命中率 ≥95%；
- 闭环：**纯网络分层集成功率 ≥70%、碰撞率 ≤10%**；
  安全门禁回退失败必须为 0、碰撞率目标 ≤5%；
- 两种报告必须同数据、同索引、同控制 seed、同重规划周期；
- **明确条款**：「干预率只作为网络安全缺口指标，不把被专家接管的回合计为网络独立成功」
  「带专家回退的成功率不能替代纯网络能力」。

本报告所有数字均按上述口径分别陈述。

## 2. 评测口径与可复现性（本轮新固证）

- **评测逐位可复现**：同 checkpoint + 同索引 + 同命令连续两次运行，
  报告的成功率、碰撞率、终点误差、失败分类**完全一致**
  （`runs/validation/nondet-1` 与 `nondet-2` 均为 67.6% / 25.7% / 0.64m / 10.6°）。
- **此前误判已纠正**：曾把 3pt 差异当作"评测噪声"，实为**换了 checkpoint**——
  `best_closed_loop.pt`（未校准停止阈值 0.5）vs `deployment.pt`（校准后 0.31）。
  **因此模型间比较必须统一使用 `deployment.pt`。**
- 守卫测试：`tests/test_evaluation_determinism.py`（含反向验证：不同 seed 必须能改变 rollout）。
- **评测集口径限制**：共享场景索引取自 `runs/validation/v13/protocol.json`（另一数据身份），
  在 v8 数据上 **204 条中 68 条无法复原，实际评估 136 条**（S1 48、S2 45、S4 28、S6 15）。
  所有版本用同一批 136 条，**横向对比成立**，绝对数字需带此限定。

## 4. 证据链：什么有效、什么无效

### 4.1 有效（有独立验证）

| 手段 | 效果 | 证据 |
|---|---|---|
| **终点位姿损失**（只压末点、航向加权 `yaw_weight=10`） | 35.3% → 58.8%，航向 74°→14.4°，**开环同时改善**（ADE 0.448→0.300m） | v19；三 seed 复现 50.0 / 52.9 / 58.8%（均值 53.9%，极差 8.8pt） |
| **配比平衡的 DAgger** | 同数据组成下成功 **+6pt**、航向 10.4°（全项目最好） | v24 vs v19 |
| **训练后排序选型**（候选排序定部署，替代训练中贪心） | 把已训出的最优权重接上部署：v17 由 epoch3(28.3%) → epoch23(35.0%) | `select_best_checkpoint()` |
| **安全门禁** | 碰撞 → **0.0%**，成功率提升 12–23pt | v25/v26 E5s |
| **BEV 输入改造**（几何 target + 语义 height） | target 空帧 59.6%→2.2%、height 由 {0,1} → 6 档语义值 | 上一轮，见 `closed_loop_five_experiment_plan.md` §0.3.3 |

### 4.2 无效或有害（已排除，勿重复投入）

| 手段 | 结果 | 证据 |
|---|---|---|
| **净空损失**（几何避障监督） | **有害**：v20 仅加它就使成功 58.8%→43.4%、碰撞 15.4%→**46.3%**、开环 ADE 0.29→0.37m；v18 三变量同改更使其崩到 ADE 1.32m | 两次独立实验 |
| **未平衡的 DAgger 采集** | **有害**：恢复集 90.8% 前进（原训练集 50.3%），整体升到 55.1%，碰撞率飙至 43.4% | v23 |
| **场景重加权**（S4/S6 ×2） | 压碰撞**几乎无效**（25.7%→23.5%），但显著提升门禁成绩与终点精度 | v25 |
| **定向 S4/S6 DAgger**（296 条平衡样本） | **未改善 S4 碰撞**（50.0% → 67.9%），总体成功维持 | v26 |
| **调标量损失权重**（`collision_loss_weight` 0/0.25/0.5/1.0 等） | 长期无提升——调的是同一个与成功判据脱钩的代理目标 | 历史 + 本轮 |

### 4.3 根因诊断（本轮固证）

1. **失败不是"停太早/轨迹预测不够远"**：失败样本历史最小距目标中位仅 **0.17m**，
   102/121 条曾逼近到 0.5m 以内；
2. **原根因是近端位姿收敛失败**：航向误差中位 74–84°、航向单调逼近比例仅 0.42
   → 已被终点位姿损失解决（航向降至 6.3–18.1°）；
3. **现根因是场景性碰撞**：碰撞发生在近端（碰撞前最小距目标中位 0.56m、
   步数中位 283/600、**无一条超时**），且高度集中于 S4（64–68%）与 S6（46–53%）；
4. **S4/S6 的碰撞是泛化失败而非记忆失败**：训练集与评测集在这些场景上
   **任务身份零重叠**（S4 430 vs 50，重叠 0）——重加权与定向补采都无法把避障行为泛化过去；
5. **定向采集采不到碰撞状态**：用 v25 在训练集 S4/S6 任务上跑闭环，
   2654 条候选里**只有 11 条是碰撞回溯**——因为碰撞发生在评测的其他任务上。

## 5. 已交付能力与已知缺口

### 5.1 可交付基线：v25/v26 + 安全门禁

- 成功率 **92.6%**、碰撞 **0.0%**、回退失败 **0**、终点位置 **0.28m**、航向 **7.6°**；
- 门禁干预率约 15%（v19 口径 781/5202），`prevented_transitions` 6/51533；
- 满足 `training_guide.md` 门禁三项判据。

### 5.2 已知缺口（如实记录）

1. **纯网络碰撞率 23.5%，高于 ≤10% 准入线**；S4 卸载区 50–68%、S6 装载面 46–53%；
2. **评测覆盖不全**：136/204 可复原；且仅覆盖 S1/S2/S4/S6 四场景，
   S3/S5/S7/S8 因索引与数据身份不匹配未纳入；
3. **只做了一轮 DAgger 配比平衡 + 一轮定向采集**，未按标准 DAgger 做"每轮用最新策略重采"的完整迭代；
4. **test 分片（S9，300 条）从未用于验收**——按流程应在 val 达标后只跑一次；
5. **开环口径**：v26 Val ADE 0.343 / FDE 0.407m 达标，但停止命中率与长度 MAE 未在本轮复核；
6. **S4 的碰撞无可靠手段**：几何避障监督（净空损失）两次证明有害，
   数据侧手段（重加权、定向补采）均无效。

## 6. 后续优化路径（按性价比排序）

### P0：先补齐评测覆盖（一切判断的前提）

- 重新构建**与当前几何/数据身份一致**的评测协议：用 `--freeze-protocol`
  在 `tracked_pivot_v8_3000/val.npz` 上冻结 300 条索引（当前已冻结但沿用了 v13 索引，
  导致 68 条无法复原）；
- 纳入全部 7 个场景（S1–S6 + S8），特别是**把 S3 紧 bay 纳入评测**——
  历史上振荡最集中的场景，本轮完全缺失；
- val 达标后**只跑一次 test（S9，300 条）**作为最终验收。

### P1：压 S4/S6 碰撞（唯一未闭合项）

按证据，只有以下方向**尚未被试过且机理成立**：

1. **几何可行性过滤（推理侧，非训练侧）**：在 NetworkSource 之后加一层
   "轨迹外廓扫掠检查"，把网络轨迹中进入碰撞的部分投影到可行域
   （类似安全门禁但作用于**轨迹**而非**整条接管**）。这与净空损失的关键区别是
   它**不改训练目标**，因此不会摧毁开环——门禁已证明"检查+回退"是有效的，
   本方案只是把它从"整条接管"降级为"局部修正"，可保留更多网络能力；
2. **按场景分别选型**：现有选型是全场景单一阈值；S4/S6 的失败模式与其他场景不同，
   可为 S4/S6 单独引入更保守的停止/减速策略（工程手段，非重训）；
3. **代价敏感损失**：对碰撞样本施加**有限**权重（而非净空损失的全局几何惩罚），
   仅对"轨迹外廓与障碍相交"的二值事件加权，避免净空距离场那种密集惩罚摧毁开环。

### P2：把 DAgger 做完整

- 标准 DAgger 是**迭代**的：每轮用最新策略重采 → 重训 → 再采；
- 本轮只做了"v19 采 → v24/v25"与"v25 采 → v26"两步；
- 若继续，需明确**采集目标是碰撞状态**，而本轮证明"均匀采偏离状态"采不到碰撞——
  应改为**只在评测暴露出的碰撞场景×任务类型上做定向重采**，或
  用**仿真对抗**（对训练任务人为注入障碍/收缩通道）制造碰撞近邻状态。

### P3：S4 场景专项（若 P1 无效）

- S4 卸载区的碰撞率 50–68% 明显高于其他场景，可能是**几何尺度与车辆尺寸不匹配**
  （车辆相对化后卸载位净空/间距偏紧）；
- 建议做**几何审查 + 场景级消融**：固定任务，只改 S4 的挡墙净空/车位间距，
  看碰撞率如何变化——这是判断"场景是否本身过于苛刻"的直接手段。

### P4：开环口径补全

- 复核 v26 的停止命中率与长度 MAE（准入线 ≥95% / ≤30 点）；
- 补 test（S9）验收。

## 7. 本轮的方法论教训（可复用）

1. **单变量纪律不可妥协**：v18 一次同改三个变量导致实验作废，
   拆成 v19/v20 后才拿到可用结论；
2. **不要用单次结果下结论**：曾据单次结果误判"DAgger 有害"（实为混淆了数据组成）
   与"v19 的 58.8% 是噪声"（三 seed 证明是稳定水平）；
3. **采集类改造必须核对分布**：DAgger 恢复集的机动配比失衡让碰撞率翻倍，
   而这一点在指标上只会表现为"成功率下降"，不易归因；
4. **开环指标不能作为闭环选型或准入依据**：本轮第 N 次复现——
   开环 ADE 在 0.267–1.32m 之间时，闭环成功率可跨越 0%–72%；
5. **先验证测量口径再优化**：评测确定性、checkpoint 口径、评测集可复原率，
   这些"测量问题"若不先解决，后续所有 ±5pt 的判断都不可靠。
