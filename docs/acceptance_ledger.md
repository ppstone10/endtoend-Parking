### 2.5 A+B 路线（全场景恢复 + hidden_dim 256）：**失败，两个硬判据被打破**

**动机**：§2.4 的结论是"7 场景下能力互相挤占"。A+B 同时针对两点——恢复样本覆盖全部 7 场景（消除挤占）
+ 容量 128→256（`hidden_dim` 同时控制 CNN 最深特征层、GRU 隐状态与全部解码投影）。

数据（`data/task_dataset/v37_dagger_allscenes/`）：600 个源任务产出 **898 条**恢复样本，
7 场景全覆盖（S1 179 / S2 167 / S3 123 / S4 196 / S5 85 / S6 127 / S8 21），
碰撞回溯 98 条（专家重标注成功率 92.5%）；合并端按机动裁剪 639/259 → 259/259，
整体前进占比 46.8% → 39.9%（原始 37.7%），最终训练集 **2918 条**。

结果（v34 协议，300 条 / 7 场景）：

| 口径 | 实测 | 准入线 | 判定 |
|---|---|---|---|
| 裸网络 E3 成功 / 碰撞 | **19.3% / 46.3%** | ≥70% / ≤10% | ❌ 全模型最差（低于 v22 的 27.3%） |
| 开环 ADE | **0.4475m** | ≤0.40m | ❌ **不满足开环准入** |
| 开环 FDE / 长度 MAE / 停止命中率 | 0.328m / 8.42 点 / 99.7% | ≤0.80 / ≤30 / ≥95% | ✅ |
| 推理耗时 | 15.45 ms/样本（**待空载复测**） | NFR-05：<10 ms | ⚠️ 见下 |
| 闭环选型得分（100 条） | 14.0% / 47.0% | — | 历史最低 |

> **关于推理耗时的更正（已复测）**：该数值是**墙钟**量，训练报告里的数在不同并发负载下不可比
> （同为 `hidden_dim=128` 的 v26 报 5.0ms、v38 报 11.6ms）。已用 `runs/diagnostics/bench_inference.py`
> 在**空载**下用同一仪器复测（`data/task_dataset/tracked_pivot_v8_3000/val.npz`，300 样本，含预热）：
>
> | 模型 | hidden_dim | 空载 ms/样本 |
> |---|---:|---:|
> | v26 | 128 | 11.29 |
> | 先导1 | 128 | 11.37 |
> | v38 | 128 | 11.30 |
> | A+B（v37） | 256 | **14.83** |
>
> 结论有两条，都与我先前的判断相反：① 128 维基线在同一仪器上**也已经超过 NFR-05 的 10ms**
> ——该需求要么已被既有模型违反，要么训练报告的口径与评测口径不是同一个量；
> ② 256 维只比 128 维慢 **31%**，不是 2.4 倍。**因此撤销"B 违反 NFR-05"这一判据**；
> B 的失败只能归因于"与从头训练混淆 + 训练预算不足"。

分场景成功率：S1 21.8% / S2 14.5% / S3 5.8% / S4 **2.0%** / S5 9.1% / **S6 70.5%** / S8 0.0%。
振荡失败 103 条（轨迹抖动为主）。

**归因（三条，按可信度）**：

1. **两个变量同时改，无法归因**——数据（全场景恢复）与"容量+从头训练"一起变了。
   为归因而起的**只改 A 的隔离实验**见 §2.6。
2. **从头训练预算不足**：256 维模型 30 epoch 后训练损失仍在 0.88–1.37（v26 最低到 ~0.63），
   val 损失剧烈震荡（1.29↔3.48），自由滚动 ADE 始终未优于 0.29。
   128 维的 v22 从零 30 epoch 能到 ADE 0.325，说明这个预算对 256 维不够。
3. ~~**B 触发了项目自己的硬约束**：`REQUIREMENTS.md` NFR-05 要求"网络 CPU 推理单次 <10 ms"，
   而 256 维实测 **15.45 ms**。因此 B 即便收敛也不可交付。~~
   **此条已撤销**——15.45ms 是并发负载下的墙钟值；空载复测为 14.83ms，且 128 维基线在同一仪器上
   也是 11.29–11.37ms（同样超过 10ms）。详见本节的更正说明与 `runs/diagnostics/bench_inference.py`。

> 结论：**A+B 不作为交付方向**。容量路线需要"更大算力预算 + 重新协商 NFR-05"，
> 在当前 CPU 仿真阶段不具备性价比；先由 §2.6 的隔离实验判断 A 单独是否有效。

S3/S8 则在所有模型上都接近 0。

### 2.7 阶段性结论与路线选择

**单模型路径在 128 维处触顶**：四次迭代（两轮先导 + A + A+B）后，
整体最好成绩停在 **E3 57.7%（先导1）/ E5 61.7%（v38）**、碰撞 **31–41%**，
距 ≥70% / ≤10% 仍有 8–12pt 成功与 21–31pt 碰撞的差距，且四次都没有单调前进。

按证据，能继续推进的只剩四条：

| 路线 | 做法 | 预期 | 成本 |
|---|---|---|---|
| **① 等预算容量对照** | h128 与 h256 **都从头训、同 epoch 数**（如各 60），唯一变量是容量 | 回答"容量是否真的是约束"这一唯一未验证的问题 | 高（各约 7h CPU） |
| **② 场景感知系统** | 运行时可从任务元数据得知场景类型 → 按场景/场景组切换专用 checkpoint | 用现有各模型的分场景最佳拼接上界：成功 **68.0%**、碰撞 **31.7%**（仍不达 ≤10%） | 低（无需重训） |
| **③ 修 S3/S8 的专家天花板** | E1r 在 S3 只有 30.8%、S8 45.5%；不解决则这两处永远贡献不了（合计 63 条 / 21%） | 决定 70% 能否达到 | 中 |
| **④ 接受并重构宣称** | 交付"v26 + 安全门禁"（P0-A 后 v34 协议：**89.0% 成功 / 0.0% 碰撞 / 回退失败 0**，三项判据全绿，见 §2.8），纯网络结果按场景如实报告，把"场景挤占"作为发现写进论文 | 不变更系统，只改口径与叙述 | 低（**已完成**） |

> 我的建议：**③ + ④** 作为论文主线（门禁已是可用系统，S3/S8 的短板有明确证据归因），
> **①** 只在你需要"容量 vs 场景数"这条科学结论时做。**②** 若要做，必须如实说明
> "场景类型由任务给出"，不能包装成泛化能力。

**后续更正（2026-10-12）：根因进一步定位到输入表征，本节四条路线已被取代。**

- 新证据（均在代码中核实）：BEV **0.25m/格**（`bev_meta.resolution`）而要通过的间隙 **0.232m**；
  `MineParkingNetV1` 三次 stride-2 后 **1 个特征单元 = 2m** 再全局平均池化；

### 2.8 P0-A 门禁三级最小风险降级：**三项判据全绿**，并推翻一条此前的根因结论

**改动**（规范 `SAFE-SHIELD-003`，详见 `spec/safety_training.md`）：门禁由"回退不可用即终止回合"
改为三级退化阶梯——主轨迹 → 可信回退 → **最小风险动作**（优先沿用上一条已验证安全参考的尾段，
否则单点原地保持）；引擎侧在"替换参考通过轨迹审查但控制器实际推进仍不安全"时同样退到最小风险动作，
`SafetyStopError` 不再是首选放弃点。

| 口径（v34，300 条） | 改动前 | 改动后 |
|---|---|---|
| 门禁 E5s 成功率（≥70%） | 78.3% | **89.0%** ✅ |
| 门禁 E5s 碰撞率（≤5%） | 0.0% | **0.0%** ✅ |
| 门禁回退失败（=0） | **2** ❌ | **0** ✅ |

| `minimal_risk_reuses` / `_holds` | — | 91 / 0 |
| 终点误差 / 路径 / 时间距离比 / 跟踪 RMS | 1.00m / 15.37m / 1.87 / 0.070m | **0.59m** / 15.96m / **1.86** / 0.070m |

分场景成功率（门禁 E5s）：

| 场景 | S1 | S2 | S3 | S4 | S5 | S6 | S8 |
|---|---:|---:|---:|---:|---:|---:|---:|

> 注意：E1r 是 30.8% 成功 + 36 条**超时**，说明专家确实**慢**；门禁能把回合维持住并让网络接手，
> 所以"专家慢"与"门禁上限"是两件事。

### 2.9 探针 0a/0b：精度下限的成因**不是**输入分辨率，而是沿时域的复合误差

完整证据见 [探针报告](probe_representation_vs_precision.md)。两个探针都设计成能否证：

| 探针 | 设计 | 结果 | 判定 |
|---|---|---|---|
| **0a** 误差–净空相关性 | 若"看不见细几何"，误差应随净空缩小而放大 | **Spearman(净空, 误差) = −0.012**；净空 0.2→1.0m，误差中位反而 0.098→0.185m | ❌ 否证 |
| **0b** 输入粗化 4 倍 | 若精度受输入细节限制，粗化必须变差 | 0.25m/格 ADE 0.3002 / FDE 0.4411 → **0.5m/格 ADE 0.2772 / FDE 0.2577（更好）** | ❌ 否证（方向相反） |

**替代解释（已成形的机制）**：同一批中途点上按轨迹相对位置分箱，误差均值
**0.197→0.251→0.275→0.359→0.490m**（单调 2.5 倍），P90 **0.319→1.008m**（3.2 倍），
中位数平坦 0.14–0.19m——典型点仍准、**远端重尾**，是"上一步输出喂下一步"的复合误差特征。
**误差最大处正是终点段**，而任务对终点的要求最严（S4 离墙 0.3m、S8 台心 ±0.2m）。

**因此**：原计划 ③（重建近场高分辨率数据集，1–2 天）**取消**；
"让解码器每步读局部几何"的依据同样被否证。新方向见交接文档 **P0-C**：
输出参数化 / 非自回归解码 / 消除 exposure bias / 多模态输出 / 缩短有效预测时域。
判据：**同时看开环 ADE 与误差沿时域的斜率**——只看总体 ADE 会被近端的好成绩掩盖。

产物：`runs/training/probe0b-{control025,coarse050}/net-v1/`、粗化数据 `data/task_dataset/coarse050_v8_3000/`
（均在 gitignore 目录，仅本地复现依据）；脚本 `runs/diagnostics/{build_coarse_bev,probe_error_vs_clearance}.py`。

### 2.10 探针 1a + 碰撞机制诊断：致碰机制是**近端固有落位误差**，不是漂移

同一天追加（完整证据见 [探针报告](probe_representation_vs_precision.md) §8）。三条被排除的候选：

| 候选 | 否证证据 |
|---|---|
| 复合误差 / exposure bias | 协议 `MPC horizon=10 × dt=0.1`、`replan_every=10` → **每次只执行前 1.0 秒（121 点里的前 5 点，其余 95.9% 每秒丢弃）**。执行窗口内 TF=0 与 TF=1 误差 0.1598 vs 0.1519（比值 **1.05**）；漂移只出现在**从不执行**的 80–100%（0.5145 vs 0.4002，比值 1.29） |
| 输入分辨率 | §2.9 已否证（粗化 4 倍反而更好） |
| 控制器跟踪 / 执行偏离 | 124 次碰撞中**执行偏离仅 10 次（8.1%）**，其余 91.9% 是参考本身不可行；碰撞时车到参考距离中位 **0.042m** |

**闭合因果链**：近端落位误差均匀 ≈**0.15–0.16m**（与净空、分辨率、TF 均无关）→ 在 **4.3%** 的样本上
执行窗口内最小净空 < 0.232m → 这些样本 **100%** 满足"窗口误差 > 窗口净空" → 参考在弧长
**中位 0.166m** 处即不可行（几乎就在起点）→ 车忠实跟随 → 真实接触。

对照：全部 2000 条不可行参考的安全前缀中位是 **3.74m**——**多数不可行在远端、从不执行**，
只影响门禁干预率，不影响碰撞。

**下一步**：一侧检验"0.15m 是不是确定性回归的下限"（测相似输入下专家示范的散布）。

### 2.11 架构 A/B（2026-10-14）：**空间通路买到稳定性、没买到能力；瓶颈在训练血统**

**假设（结构性证据）**：`model/variants.py:133-154` —— `net-v1` 的 BEV 编码器以
`nn.AdaptiveAvgPool2d(1)` 结尾，解码器只拿到「整张 BEV 的全局平均 + 目标位姿 3 数 + 状态 2 数」，
**无任何空间通路知道障碍在哪**。这也回头解释了 §2.9 两个探针：0a（净空–误差不相关）与
0b（粗化反而更好）在该架构上都是**循环论证**——网络看不见细节，"细节无影响"是必然结果。
`net-v2`（U-Net 跳连 + 目标条件交叉注意力）已实现但从未训练。

**设计**：先导1 的成绩来自**暖启动**（`v22-7scenes-no-dagger`），而 v2 无法从 v1 权重初始化，
故设**冷启动 v1 对照**。两配置逐字段一致（同数据/val、同 20 轮、同 seed 20260827、同损失、
同闭环选型节奏），**唯一差别是模型**。

**结果（v34 半协议 150 条，E3 纯网络）**：

| 配置 | 开环 ADE | 成功 | 碰撞 | 抖动 | 振荡失败 |
|---|---:|---:|---:|---:|---:|
| v1 暖启动（先导1 `epoch0009`） | 0.3236 m | **58.0%** | **41.3%** | **5.4%** | 1 |
| v1 冷启动（对照） | **0.3232 m** | 33.3% | 49.3% | 7.1% | 26 |
| v2 空间架构（冷启动） | 0.4351 m | 33.3% | **66.0%** | 11.1% | **1** |

**三条结论**：

1. **架构不是瓶颈**：v2 的协议成功率与 v1 冷启动**完全相同（33.3%）**，碰撞反而更高
   （66.0% 对 49.3%）。一次性目标条件交叉注意力**没有提高成功率**。
2. **开环精度完全不预测闭环结果**（首次受控 A/B）：两个 v1 的开环 ADE 几乎相同
   （**0.3236 对 0.3232**），闭环成功率相差 **24.7 个百分点**。
3. **58% 来自训练血统**：58.0% 与 33.3% 两个模型在架构、数据、seed、配方上完全一致，
   **唯一差别是初始化血统**（v22 → v35-pilot → 先导1）。
4. **空间通路确实买到稳定性、但换成了碰撞**：v2 冷启动即达 `振荡失败 1`（与 v1 暖启动同级），
   v1 冷启动有 26 次；但 v2 把它换成了 66.0% 碰撞，而不是成功。

**工程附注**：v2 推理 **62.7 ms/样本**，超出 NFR-05 的 <10ms 六倍（25600 token 注意力）。

**路线含义**：改架构不是提升纯网络成功率的杠杆；**"暖启动 + 数据迭代 + 逐轮闭环选型"
是本项目唯一被证明有效的杠杆**（v16 11.0%→33.8%、v38→65%/28%、先导1 58.0%）。

**未验证缺口**：v2 可能因 20 轮未收敛被低估（ADE 0.435 明显差于 v1 冷启动 0.323）；
Tier 3（逐步空间注意力）未测；目标 ≤10% 碰撞与三者（41.3%–66.0%）相距甚远。

产物：`configs/training/{net-v2-spatial-cold,net-v1-cold-control}.yaml`；
`runs/training/ab-v2-spatial/`、`runs/training/ab-v1-cold/`、`runs/validation/arch-ab/`（均 gitignore）。

- **第二轮在协议上略低于第一轮（−1.0pt 成功 / +2.4pt 碰撞，约 3 个回合，在噪声内）**，
  且开环明显退化（ADE 0.2027→0.3362、航向 MAE 7.6°→28.4°）。
  选型阶段它也已低于自己的起点（80 条子集 63.7% 对起点 66.2%）。
- **原因（有数据支撑）**：同一杠杆在起点变强后自动变弱——策略碰撞更少（41.3%→30.3%），
  **可回溯的碰撞状态更少**（新采 712 对 898；平衡后 314 对 518）；起点本身更强（可提升空间更小）。
- **结论**：**"更多碰撞状态 DAgger"这条杠杆在 ~62%/30% 处达到平台。**
  累计效果仍为真实提升（相对先导1：成功 +4.6pt、碰撞 −11.0pt），但**一次台阶，不是持续斜坡**。
- **缺口现状**：成功 62.3%（≥70%，差 7.7pt）；**碰撞 30.3%（≤10%，差 20.3pt）——碰撞是唯一的大缺口**。

**未达标差距**：成功 64.7%（目标 ≥70%，差 5.3pt）；碰撞 29.3%（目标 ≤10%，差 19.3pt）。

## 5. 根因（本轮固证，三条互不替代）

1. **训练场景覆盖不足**：v26 的训练集 `v25_dagger_s46/train-balanced.npz` 只含
   S1 467 / S2 438 / S4 1105 / S6 686，**S3/S5/S8 一个样本都没有** → 这三场景闭环成功率 0%、碰撞率 100%。
2. **只补场景覆盖不够**：v22 用全 7 场景 `tracked_pivot_v8_3000/train.npz` 训练，
   学会 S5（0%→54.5%），但丢掉 S1/S2/S4/S6（S6 38.6%→2.3%、S2 94.5%→43.6%），
   S3/S8 仍近 0。→ 需要"全场景数据 + 已积累的配方（终点位姿损失 + 配比平衡 DAgger）"两者叠加。
3. ~~**专家滚动重规划本身在紧场景吃力**……与门禁在这两处的上限（36.5% / 45.5%）一致
   → **门禁天花板受专家回退质量限制**。~~
   **此条已被 §2.8 推翻**：专家的滚动重规划能力完全没变（E1r 仍 S3 30.8% / S8 45.5%），
   但同一批 300 条上门禁把 S3 提到 **80.8%**、S8 提到 **72.7%**。
   那两处门禁的上限**不是**专家能力，而是**安全层过早终止回合**。
   E1r 仍是"专家单独规划"的能力事实（且失败几乎是超时，说明专家**慢**而非不能），
   但不能再用它解释门禁上限。
