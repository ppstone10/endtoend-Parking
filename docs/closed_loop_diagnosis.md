## 3. 根因诊断（确定性证据）

### 3.1 决定性证据

v7 原本成功的 11 条样本，在 **5 个安全微调模型（w=0.25/0.5/1.0/w=0/TF课程）下完全一致地失败**（8 条振荡 + 3 条碰撞）。由此可证：

- ❌ **净空损失权重不是根因**：w=0（彻底关闭净空）开环最优、碰撞率反升，但失败模式不变。
- ❌ **teacher forcing 课程不是根因**：恢复 v7 式 1.0→0.2 衰减后结果与 v9 持平（8.8%/44.1%）。
- ✅ **根因在"安全微调路径本身"**：v7 权重 + 恢复数据 + 微调这一组合系统性破坏了 v7 已学到的闭环滚动能力。

### 3.2 当前唯一未解瓶颈：振荡

- 门禁把 34 条中全部碰撞转为 `safety_stop`（0 碰撞、0-1 回退失败），剩余失败 **100% 是振荡**。
- 振荡样本终态位置误差仅 0.2–1.2m（已接近目标），但航向偏差 15–117°，600 步跑满。
- 即：车辆能到达车位附近，但**航向无法收敛**，每 10 步重规划时网络轨迹方向反复切换，MPC 来回摆动。

### 3.3 开环-闭环为何脱节

- 开环只测"从数据集起点一次性预测的轨迹 vs 专家轨迹"的误差，不经过状态演化。
- 闭环是"感知→BEV→预测→MPC→推进→再感知"的**自持状态循环**，误差会在滚动中累积；网络在闭环诱导状态分布上的泛化才是成功关键。
- 恢复数据（258 条，仅占 9.7%）本意是覆盖闭环状态，但量太少且分布与各安全模型实际到达状态不完全一致，DAgger 只做了半轮。

### 3.4 方向 B 已定论：振荡是"近端停止长度预测提前 + 终点航向回归偏差"

对 v7（成功）与 v9（振荡）同样本做逐重规划对比，锁定振荡机制：

| 指标（车辆距目标 <3m 时） | v7（成功） | v9（振荡） |
|---|---|---|
| 预测轨迹长度 | 3.7→1.7m 缓慢收缩 | **骤缩至 0.7–1.9m** |
| 预测终点距目标 | 0.8–1.5m 稳定 | **膨胀至 1.5–2.5m** |
| 预测终点航向误差 | 0.06–0.23 rad | **膨胀至 0.4–1.3 rad** |
| 轨迹方向切换 flips | 0 | **1–2** |

- 机制：车辆接近目标时，v9 停止头提前触发，预测轨迹缩到约 37–40 点（MPC 参考过短），且终点离目标仍远、航向偏大、含方向切换；MPC 追着一条"短而偏航"的轨迹来回摆动 → 振荡。
- **不是滚动重规划机制问题**（v7 用同一引擎+机制可成功），而是**网络近端轨迹预测质量退化**。
- 诊断脚本：`scripts/diagnose_oscillation_focus.py`、`scripts/diagnose_oscillation_compare.py`。

### 3.5 更深层根因（v10 实验新发现）：净空损失与"到达目标"物理冲突

v10 近端对齐实验（`SAFE-LOSS-003`，w=0.5）两种形式都导致纯网络闭环更差：

| 变体 | 监督对象 | 纯网络成功 | 纯网络碰撞 | 门禁成功 |
|---|---|---|---|---|
| v10 (goal 对齐) | 目标位姿 | 0.0% | 73.5% | 35.3% |
| v10-fix (target 对齐) | 专家轨迹末端 | 2.9% | 52.9% | 32.4% |

且 `train_collision_loss` 从 v9 的 0.09–0.18 升到 0.29–0.53。逐样本检查净空场发现：**19/300 样本的目标位姿处净空仅 0.125m，远低于 `required_clearance=0.3m`**（`collision_margin 0.2 + extra 0.1`），且这些样本轨迹末端 8 点中多数处于 <0.3m 净空区。分布：S1×4、S2×7、S3×3、S4×1、S6×1、S8×3。

**L2 访问状态归因（v10-fix vs v7，34 条）**：整体 vs_ADE 0.439m（略优于 v7 的 0.499）、vs_FDE 0.609（优于 0.768），但**近端航向误差 71.5°（v7 为 50.4°）、方向切换 0.944（v7 为 0.567）、跨重规划航向跳变 2.471 次/样本（v7 为 0.029）**——近端对齐监督虽然降低了整体位置误差，却破坏了近端航向收敛与跨重规划一致性，是纯网络碰撞率升至 52.9% 的直接原因。

**结论**：专家轨迹末端本就在车位内贴目标停车，物理上无法满足 0.3m 净空。净空损失对末端天然惩罚，与"轨迹必须到达目标"根本对立：
- 网络可选①绕开目标（缩短轨迹）→ v9 的"净空降 90.9% 但闭环振荡"；
- 网络可选②强行贴目标 → v10 的"净空差、碰撞暴增"；
- 近端终点对齐（v10-fix）→ 位置略好但航向回归与一致性更差，仍不可用。

### 3.5b 净空目标豁免实测（v11）：放宽净空不能解决闭环

实现 `SweptFootprintLoss` 目标豁免（`safety_goal_exempt_radius_m`/`safety_goal_exempt_weight`，对距目标 `radius` 内扫掠点平滑降权净空惩罚、保留越界惩罚），v11 配置：豁免半径 1.0m、豁免权重 0.0（目标处完全豁免净空），其余同 v9 正式。

结果：纯网络 0% 成功/47.1% 碰撞，门禁 38.2%（低于 v9d 的 47.1%）；开环 0.237/0.491m、净空损失与 v9 相当（豁免区本就少有点）。失败样本与 v9 高度一致。

**结论**：即使完全豁免目标附近净空，网络仍不收敛到目标。说明闭环失败不是"净空约束过强"单独导致，而是**安全微调整体（净空+恢复数据+微调组合）改变了网络权重分布，使其在滚动重规划时无法生成稳定的入位轨迹**。豁免只是必要条件而非充分条件。

### 3.6 恢复数据隔离结论（方向 A）

- 用纯 v7 数据（无恢复）微调（v9d）：门禁成功率升至 47.1%（当前最高），但 v7 成功 11 条仍全部失败 → 恢复数据非根因、有加重作用。

## 4. 两个待决策方向（已立项）

### 方向 A：恢复数据是元凶？

- **假设**：258 条恢复样本（9.7%）混入微调引入分布冲突，冲淡了 v7 原始 2400 条的监督，导致滚动能力退化。
- **实验**：从 v7 `best.pt` 权重初始化，但**只用原始 v7 train（2400 条，无恢复）**做同等微调，统一复算净空 + 同索引闭环。
- **判据**：若纯网络成功率恢复到 ≥ v7 的 32.4% 附近且振荡减少 → 恢复数据确为元凶；否则排除。

### 方向 B：振荡是滚动重规划机制问题？——已定论 ✅

- **诊断结论**：非滚动重规划机制问题（v7 用同一引擎+机制可成功），而是安全模型近端轨迹预测退化：车辆距目标 <3m 时停止长度预测提前触发（轨迹骤缩至 0.7–1.9m）、预测终点距目标膨胀至 1.5–2.5m、终点航向误差膨胀至 0.4–1.3 rad、轨迹含 1–2 次方向切换；MPC 追着"短而偏航"的参考轨迹来回摆动 → 振荡。
- **证据**：`scripts/diagnose_oscillation_focus.py`、`scripts/diagnose_oscillation_compare.py` 逐重规划对比 v7/v9，见 §3.4。
- **疑似根因**：净空损失诱导网络"用缩短轨迹规避障碍"（短轨迹天然远离障碍、净空损失更低），牺牲终点收敛。
- **建议解法**：a) 训练时抑制"缩短轨迹躲障碍"倾向（停止长度监督与净空损失再平衡、近端终点/航向加权）；b) 单变量评估缩短重规划周期能否在近端救回收敛；c) 若确认净空诱导，回方向 A 重新审视恢复数据占比。

### 方向 A：恢复数据是元凶？——已定论：非根因但有加重作用 ✅

- **实验**：从 v7 `best.pt` 初始化、只保留 `collision_loss_weight=0.5` 与净空损失，但训练集**只用原始 v7 train（2400 条，无 258 条恢复样本）**（`configs/training/net-v1-safe-v7data.yaml`），其余与 v9 正式配置完全一致 → 单变量隔离恢复数据。
- **结果**：v9d 纯网络 11.8% 成功（4/34）/35.3% 碰撞，门禁 47.1% 成功/0 碰撞/0 回退失败。
- **判定**：v7 成功 11 条在 v9d 下**仍全部失败**（8 振荡 + 3 碰撞）→ **恢复数据不是唯一元凶**；但 v9d 相对 v9 明显改善（成功 2.9%→11.8%、碰撞 44.1%→35.3%、门禁 41.2%→47.1%）→ **恢复数据确实加重退化**（疑似 9.7% 占比冲淡原始监督且分布错配）。
- **结论**：根因是"安全微调路径本身"（近端预测退化，见方向 B），恢复数据是加重因子，需在方向 B 解法基础上重新设计恢复数据来源（用安全模型自身 deployment 采集）与占比。

## 5. 系统性困难与解决路线

### 5.1 困难分层

| 困难 | 性质 | 现有手段 | 缺口 |
|---|---|---|---|
| 开环/闭环脱节 | 结构性 | 恢复数据(DAgger半轮) | 状态分布覆盖不足，占比仅 9.7% |
| 振荡(近端停止提前+航向不收敛) | 训练+机制 | 累计停止监督、门禁 | 无近端终点/航向专项监督，净空损失可能诱导缩短轨迹 |
| 碰撞 | 已解决 | 净空损失+执行前门禁 | 门禁 0 碰撞、0 回退失败 ✅ |
| 安全微调摧毁 v7 能力 | 已定位 | — | 近端预测退化(方向B定论)；恢复数据为加重因子(方向A定论) |

### 5.2 解决路线（按优先级）

1. **停止对安全微调路径做单变量修补**：v9/v10/v11 系列已证明"净空损失、近端对齐、目标豁免"都无法恢复闭环，且近端对齐破坏跨重规划一致性。继续调这些权重组合是低效投入。
2. **回归 v7 基线能力**：v7 纯网络 32.4% 仍是当前最高纯网络成功率，是进一步工作的起点而非安全微调。
3. **恢复数据的 DAgger 完整化**：用**当前纯网络自身 deployment**（而非 v7）在闭环访问状态重采恢复数据，覆盖其真实到达状态；这是方向 A/B 定论后的训练侧正道。
4. **验证阶梯 L1–L4 已可用**：BEV 保真（L1）、访问状态轨迹质量（L2）、单周期 MPC 跟踪（L3）、顶层效率判据（L4）已落地，可直接用 L2 报告作为训练侧改进的验收，而不是只看成功率/碰撞率粗口径。
5. **门禁作为运行基线**：门禁 0 碰撞/0 回退失败可作阶段交付的"安全防线"指标，但不得计作纯网络能力。

## 6. 验收定义速查

- **开环**（training_guide「正式验收」）：ADE≤0.40、FDE≤0.80、长度 MAE≤30、|偏差|≤20、停止命中≥95%；安全训练再加"统一净空损失较 v7 ≥10% 下降"。
- **闭环**（training_guide:66）：纯网络分层集成功率≥70%、碰撞率≤10%；门禁回退失败=0、碰撞率≤5%；两报告必须同数据、同索引、同 seed、同重规划周期。
