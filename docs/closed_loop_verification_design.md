# 闭环验证设计与三步可验证执行路线

> 状态：设计已定稿，作为论文实验期闭环改造的对照基准。
> 最后更新：2026-08-31

## 1. 背景与目标

当前阶段（Python 仿真、论文实验期）的核心矛盾：

- **开环验收**全部通过（v7 ADE/FDE 0.272/0.568m；v9 系列 0.17–0.27/0.30–0.49m），但指标是"自指"的：专家轨迹由与网络输出同一套几何/算法的规划器生成，开环又只在数据集起点做一次性预测，完全落在训练分布内，故极易达标。
- **闭环验收**长期不过：纯网络成功率 32.4%（v7）至 2.9–17.6%（v9 系列），目标 ≥70%。已定论根因：安全微调导致近端（距目标 <3m）停止长度预测提前、终点距目标与航向误差膨胀、轨迹含方向切换 → MPC 追着"短而偏航"的参考轨迹来回摆动（振荡），振荡占门禁剩余失败 100%。
- **定位成本高**：当前只有"开环↔全闭环"两级，闭环失败无法归因到感知、规划、控制中的哪一层，只能靠反复调参。

**目标**：把"感知→BEV→轨迹规划→MPC→执行"这条主线拆成每一步都有可追踪效果点的验证阶梯，一块一块接通，最终保证全闭环达标；同时让纯仿真阶段的方案在 CARLA 与实车上可复现。

## 2. 网络与行业方法调研结论

调研基于可访问的权威来源（网络访问受限，arxiv/google/github/waymo 不可达；以下为可达来源与既定文献知识）：

| 来源 | 可复用方法 | 与本项目的对应 |
|---|---|---|
| NVIDIA DRIVE/Isaac 官方 | **闭环仿真为主验证、开环只用于数据扩展与训练**："Open-Loop: generate diverse sensor data without policy in the loop；Closed-Loop: generate next frame reactive to decisions"。安全验证必须在闭环场景中做 | 印证本项目"开环只作必要不充分门槛、闭环才是验收"；开环+闭环分层与 NVIDIA 口径一致 |
| CARLA 官方 | 仿真支持**开发/训练/验证**；可**记录并精确重放同一回合**，以在不同传感器/配置间重复对比；传感器套件可替换 | 印证三阶段"只替换传感器来源与底盘接口、其余模块不动"的可复现迁移路径 |
| DAgger（Ross et al., 2011，行为克隆复合误差的经典解法） | 用**学习器自身策略**闭环访问的状态重标注专家标签，迭代消除分布偏移 | 本项目恢复数据采集即是"半轮 DAgger"；完整化需用当前模型自身 deployment 重采 |
| 业界分层规划（AVP/APA 通用架构） | **全局路径规划（参考轨迹）+ 局部轨迹规划 + 跟踪控制**分层；局部层只需短程正确，可纠正全局误差 | 对应路线 B；短距局部规划是工业实现标配 |

**调研缺口**：因网络受限无法直接引用 Waymo/华为/小鹏等具体企业文献原文；上述结论基于 NVIDIA/CARLA 官方页与 DAgger 等既定文献知识，属高置信度的成熟方法。

## 3. 路线判断：全局单次循迹 vs 全局参考 + 局部重规划

用户提出的两条路线：

- **路线 A**：规划一整条到终点的轨迹，MPC 全程循迹（一次规划、全程跟踪）。
- **路线 B**：先规划完整轨迹作为参考，再通过**短距离轨迹规划（以完整轨迹为参考）** + MPC 跟踪完成实际运动。

**判断：路线 B 为主，路线 A 保留为对照口径。**

理由：

1. **路线 A 对网络不可靠**：一次全轨迹预测的任意误差会在长距离跟踪中累积，且无状态反馈纠正。这正是"开环达标而闭环失败"的结构性原因——开环测的恰好是"单次全轨迹 vs 专家"，闭环需要的是"滚动状态下的局部正确"。对专家轨迹路线 A 已证明可行（M1 98.5%），但对网络不可作为主线。
2. **路线 B 是业界分层标准**：全局层只需提供长期意图与走廊，局部层只需在当前状态附近短程正确。近端退化（当前唯一瓶颈）通过"局部规划 + 每 K 步重规划"即可纠正，不必强求网络全程预测精确。这也是 AVP/APA 的通用架构，迁移到 CARLA/实车时结构与接口都不变。
3. **当前系统已接近路线 B**：`replan_every=10` 的滚动重规划已存在，缺的是"以完整轨迹为参考的短距局部规划"这一显式层级。补齐该层后，网络近端只需局部正确，且失败可归因。

**网络在路线 B 中的角色**：为保证"端到端"论文纯度，网络同时承担全局参考与局部轨迹生成；当网络近端不可靠时，用经典规划器（专家回退）或安全门禁作为局部兜底——该机制已存在（`SafetyShieldSource`/`ReplanningExpertSource`），不是替代纯网络能力，而是独立防线。

## 4. 三步可追踪效果点（验证阶梯）

把主线拆成四个验证层，每层有独立的输入、输出、指标与验收线；任一层失败都能先定位到该层，而不是整体调参。

```
L1 感知→BEV 保真度        （隔离：传感器/BEV 是否失真）
L2 轨迹规划质量           （隔离：网络在闭环状态上是否预测正确）← B 指标所在
L3 单周期 MPC 跟踪质量    （隔离：控制是否跟踪得住）
L4 全闭环组合             （顶层判据：成功率/碰撞/终点位姿/时间-距离效率比）
```

### L1 · 感知→BEV 保真度（新增层）

- **输入**：传感器帧（LiDAR/Camera，含噪声档）+ 场景真值。
- **指标**：BEV occupancy 通道 vs 场景几何真值的 IoU/精度/召回；target 通道命中率；height/density 通道误差。按 noise_level（clean/low/high）输出退化曲线。
- **验收线**：真值 BEV 应接近 1.0；clean 下 IoU ≥ 阈值（建议先实测标定）；high 噪声下不出现系统性遮挡/漏检。
- **实现入口**：`sensor2bev/`、`sim/scenes.py` 场景几何、`sim/noise.py`。用场景 obstacle 集合直接栅格化真值 occupancy，与 `LiDAR2BEV`/`BEVFusion` 输出同构比较。
- **目的**：把"感知失真"从规划问题中分离。若 BEV 已失真，后续任何规划/跟踪都无意义。

### L2 · 轨迹规划质量（B 指标所在层）

- **输入**：闭环滚动过程中记录的每个重规划状态 + 网络预测轨迹 + 专家在该状态的重规划。
- **指标**（开环误差在**闭环诱导状态**上计算，而非数据集起点）：
  - 访问状态开环误差：网络预测 vs 专家重规划的 ADE/FDE/航向 MAE；
  - 近端质量：距目标 <3m 时停止长度、预测终点距目标距离、终点航向误差、方向 flips（这是振荡的直接度量）；
  - 跨重规划一致性：相邻两次重规划的轨迹终点/方向突变次数。
- **验收线**：近端终点误差与航向误差收敛到与专家同量级；flips 应为 0；不一致性应接近 0。
- **实现入口**：`scripts/diagnose_oscillation_*.py` 已是雏形，固化为 L2 标准报告。
- **目的**：把振荡从"600 步跑满才失败"变成"重规划阶段即可量化的退化"。B 是这一层的尺子。

### L3 · 单周期 MPC 跟踪质量（用户点名的"单周期闭环"）

- **输入**：参考轨迹（先专家、后网络）+ 车辆模型 + MPC。
- **指标**：单周期内跟踪横向 RMS、到达率、扰动恢复（推离 0.5m 拉回）、控制量平滑度。
- **验收线**：专家轨迹 + MPC 已在 M1 达成 98.5% 成功率、跟踪 RMS 0.037–0.047m——控制层健康这一前提已由 `LOOP-GROUND-001` 固证；单周期口径应保持该水平。
- **实现入口**：`controller/mpc.py`、`runtime/engine.py`、`experiments/ground_baseline`。
- **目的**：把"MPC 跟踪效果"变成可单独复核的层。若 L3 健康而 L4 失败，故障必在 L1/L2。

### L4 · 全闭环组合（顶层判据）

- **输入**：完整主线（感知→BEV→网络→MPC→推进→再感知）。
- **指标与验收**：见 §7 顶层判据。
- **实现入口**：`experiments/closed_loop_evaluation.py`（同索引/同 seed/同重规划周期）。

## 5. B 与 C 如何影响效果实现

用户对 B/C 的作用不明确，此处给出精确关系：

- **A（本设计的验证阶梯）是框架**：定义每一步可追踪的点。
- **B（跨重规划一致性与近端轨迹质量指标）是 L2 的度量**：它把当前唯一瓶颈"振荡"翻译成训练与评测都能观测的量（近端停止长度骤缩、终点距离/航向膨胀、方向 flips）。没有 B，L2 层只能用 ADE/FDE 掩盖近端退化——这正是"开环很漂亮、闭环一直振"的原因。
- **C（训练侧）是让 L2 达标的手段**：
  1. **近端终点对齐监督**（`endpoint_alignment_loss`，已实现为 `SAFE-LOSS-003`、v10 配置）：对轨迹末端 K 点相对目标位姿加权，直接压制"缩短轨迹躲障碍"倾向——这是方向 B 定论后的训练侧解法；
  2. **恢复数据用当前模型自身 deployment 重采**（DAgger 完整化）：现有 258 条恢复数据是 v7 deployment 采集的，与各安全模型实际到达状态错配；方向 A 已定论恢复数据是加重因子；
  3. **恢复占比与采样策略再平衡**（消融已定论真实占比 shuffle）。
- **一句话**：A 决定测什么，B 决定怎么测才有预测力，C 决定网络能否通过 B 的尺子。三者最终都落在"轨迹规划"这一步上，因此路线 B 的"短距局部正确"正是它们的共同着力点。

## 6. 逐步组合协议（一块一块接通）

每层先独立达标，再按顺序接通，接通前必须留"实现前失败证据"：

1. **L1 独立**：BEV 保真度达标 → 感知层不再成为闭环失败的可疑来源。
2. **L2 独立**：在闭环诱导状态上轨迹质量达标 → 规划层不再成为可疑来源。
3. **L3 独立**：单周期跟踪质量复核达标 → 控制层不再成为可疑来源。
4. **组合 ①+L2**：真 BEV + 网络轨迹 → MPC 单周期，验证"规划+控制"链。
5. **组合 ①+②+L3**：完整 L4 全闭环，验证顶层判据。

任一环节失败，先回到对应层修其独立指标，不跨层调参。每层验收写入同一数据/索引/seed/重规划周期的统一复现协议（已具备）。

## 7. 顶层判据（L4 验收口径）

用户提出的三条判据全部纳入，并补齐异常检测量化：

| 判据 | 量化指标 | 现状 |
|---|---|---|
| 终点位姿偏差 | `final_pos_err`、`final_yaw_err` 低于车位自身容差 | 已实现（`TerminalChecker`/`EpisodeResult`） |
| 是否碰撞 | `collision_rate`（纯网络 ≤10%，门禁 ≤5%） | 已实现；门禁 0 碰撞 |
| 时间-实际距离比值异常 | 新增**效率指标** `time_dist_ratio = parking_time / path_length`（s/m）；对比专家基线与 `plan_v` 理论下界，异常高说明振荡/绕路/停止过频 | 需新增；与专家基线同组对比 |
| （补充）蜿蜒度 | `path_length / 起终点直线距离`，异常高说明绕路 | 需新增 |
| （补充）失败分类 | `oscillation/collision/timeout/pose_error` | 已实现 |

效率指标不替代振荡分类，而是提供"绕路/空转"的连续度量，便于训练早停与模型对比。

## 8. CARLA / 实车可复现路径

- 三阶段共享同一接口契约（`interfaces/`），只替换**传感器来源**与**底盘执行接口**（`NFR-03`）。
- 验证阶梯逐阶段复用：
  - L1：CARLA 用真值语义分割/深度做 BEV 保真对比；实车用建图真值对比——口径不变。
  - L2：同一网络、同一访问状态采集协议；实车改为真实状态估计。
  - L3：同一 MPC，替换车辆模型参数（CARLA 车辆/履带底盘）。
  - L4：同一闭环引擎与指标聚合。
- 每阶段以"同接口、同指标口径、同复现协议"验收，保证 Python 仿真结果可逐步外推到 CARLA 与实车，而不是重新搭一套验证体系。

## 10. 落地顺序（建议）

1. **L1 BEV 保真评测**（新增脚本 + 指标，成本最低、独立性强）。**✅ 已完成 v1**：`metrics/bev_fidelity.py` + `scripts/evaluate_bev_fidelity.py`，occupancy 采用"高分辨率 LiDAR 采样真值"主口径与"几何真值"参考口径，target 用车位矩形真值；输出逐场景×噪声档 IoU/Precision/Recall/命中率与退化曲线。实测 9 场景：clean occ IoU 0.53–0.63（LiDAR 稀疏性致召回不饱和）、high 退化至 0.35–0.48、target 命中率 0.93–0.99。
2. **L2 固化访问状态轨迹质量报告**（把诊断脚本提升为验收报告，纳入闭环评测输出）。
3. **L3 单周期跟踪复核**（专家基线已证，补充网络参考单周期口径）。
4. **L4 顶层判据补齐**（效率指标 `time_dist_ratio`、蜿蜒度）。
5. **C 训练侧**：执行 v10（近端对齐）训练与同索引闭环准入；成功后用 v10 deployment 重采恢复数据，迭代 DAgger。
6. **路线 B 落地**：以完整轨迹为参考的短距局部规划层（用网络局部输出，专家/门禁兜底），验证近端振荡是否被局部层吸收。
