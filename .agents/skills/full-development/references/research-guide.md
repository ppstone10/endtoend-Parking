# 新方案调研指南

仅在新功能、新方法、新依赖、新协议或项目内没有成熟先例时读取。

## 最小调研流程

1. 从用户目标和项目硬约束提炼 1～3 个决策问题。
2. 通常查阅 2～4 个来源，优先级为：官方文档或标准、官方参考实现、成熟产品技术资料、维护良好的开源实现。
3. 只提取候选方法、适用条件、主要取舍、失败模式，以及许可证、安全、兼容性和维护成本。
4. 对照项目现有架构与非目标，选择最小适配方案；不得为了追随流行做法引入无必要复杂度。
5. 两个高质量来源给出一致结论且已覆盖重大风险时停止；不同来源存在实质冲突时再扩大搜索。

## 调研结果

在实施前用简短内容说明：

- 查阅了哪些来源；
- 提取了哪些可复用方法；
- 选择什么、没有选择什么以及原因；
- 哪些结论仍属于推断或未验证。

标准档可只在对话中保留结果。重大或关键档、长期架构决策或复杂证据应使用 `track-change-trace` 追加到当天 TRACE 的对应任务编号；只有存在真实长期备选方案时才创建决策记录。
