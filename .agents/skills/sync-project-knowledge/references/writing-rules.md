# 写作规则

- README 与 ARCHITECTURE 使用当前事实口吻。
- DESIGN 中明确区分计划行为与已实现行为。
- DESIGN 保存项目级目标与整体行为；功能级稳定规范 ID、验收和追溯只放在对应 Spec。
- Spec 按功能或领域拆分，只读取和更新受影响文件；不得让单一追溯矩阵无限增长。
- 优先链接，不重复解释。
- 每天一个 TRACE 文件；已知时间的任务和检查点自上而下从旧到新排列，并通过追加检查点保留演进。
- 每日 worklog 自上而下按真实时间从旧到新排列，只保存任务执行索引；不得从中推导当前项目事实，也不得复制 TRACE 的完整证据。
- 原始证据放入 TRACE，可复用结论放入 LEARNING。
- TRACE 结论变化时追加更正或取代事件，不改写已经发生的检查点。
- LEARNING 条目必须包含可搜索的触发词，并解释规则存在的原因。
- 替换行为时删除过期说法，不在概述文档中保留历史。
- 不得仅因为附近代码变化而更新文档。
- 除必要路径、命令、代码标识符、标准名称和专有名词外，使用中文。
